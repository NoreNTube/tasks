# Задачи — сайт с синхронизацией через Google Таблицу

Мини-приложение со списком задач, которое открывается как обычный сайт (GitHub Pages),
работает на телефоне и на компьютере, а данные хранит в **вашей Google Таблице**.
Никаких серверов, баз данных и сборки — только статические файлы и Google Apps Script.

```
Телефон (Safari/Chrome) ─┐
                         ├── сайт на GitHub Pages ── Apps Script ── Google Таблица
Компьютер (Chrome/Edge) ─┘        (localStorage-кэш)      (JSON API)
```

## Что умеет

- Добавлять, редактировать, отмечать выполненными и удалять задачи.
- **Цвета задач** (8 цветов + «без цвета») — полоска и подсветка карточки.
- **Иконки задач** — 24 встроенных эмодзи (📅 💰 🏠 …) или «без иконки»; видны в карточке и синхронизируются.
- **Акцентный цвет интерфейса** — 9 вариантов (включая чёрный и белый); меняет кнопки,
  подсветки, ссылки и бейджи. Настраивается в «Настройках» отдельно на каждом устройстве.
- **Срок** — дата и необязательное время, быстрые кнопки «Сегодня / Завтра / Через неделю» и приоритет.
- **Подзадачи** с галочками и прогрессом прямо в списке (`✓ 2/5`).
- **Фотографии**: до 12 штук на задачу, сжатие в браузере, просмотр и скачивание.
- Заметки, поиск и фильтры «Все / Активные / Готово».
- **Автоматическая синхронизация**: при запуске, после каждого изменения, раз в минуту,
  при возврате на вкладку и при появлении интернета.
- **Офлайн-режим**: всё сохраняется на устройстве и отправится в таблицу, когда появится сеть.
- Устанавливается на телефон как приложение (PWA), есть тёмная тема.
- Синхронизация нескольких устройств без конфликтов: побеждает последнее изменение.

## Быстрый старт

Нужны только браузер и Google-аккаунт. Git и Node.js не обязательны.

### Шаг 1. Google Таблица + Apps Script

1. Создайте новую таблицу: <https://sheets.new> (название любое, например «Задачи»).
2. В таблице откройте **Расширения → Apps Script**.
3. Удалите весь код в редакторе (`Ctrl+A` → `Delete`).
4. Откройте файл [`apps-script/Code.gs`](apps-script/Code.gs) из этого проекта,
   скопируйте его целиком и вставьте в редактор.
5. В самом верху найдите строку:
   ```js
   TOKEN: 'CHANGE_ME_на_длинный_секрет',
   ```
   Замените значение на свой длинный случайный секрет (30+ символов), например
   `k7Qm2vX9pL4tR8sW1cN6bY3dF5hJ0aZ`. Запомните его — он понадобится в приложении.
6. Сохраните: значок дискеты или `Ctrl+S`.
7. Нажмите **Развернуть → Новое развертывание**:
   - тип — **Веб-приложение**;
   - **Запуск от имени**: `Я` (ваш аккаунт);
   - **У кого есть доступ**: `Все` (Anyone) — это обязательно, иначе браузер не сможет
     обратиться к скрипту;
   - нажмите **Развернуть**, при запросе авторизации разрешите доступ своему аккаунту.
8. Скопируйте **URL веб-приложения** — он заканчивается на `/exec`:
   `https://script.google.com/macros/s/AKfycb.../exec`

> Листы `tasks` и `photos` с заголовками создадутся сами при первом обращении.
> Если в таблице уже есть лист `tasks` от прошлой версии, новые колонки
> `color`, `subtasks`, `photos` добавятся автоматически — данные не потеряются.
> Сделать это заранее можно функцией `setupSheet` в редакторе Apps Script.

### Шаг 2. Публикация на GitHub Pages

1. Зарегистрируйтесь на GitHub (если ещё нет аккаунта) и создайте репозиторий,
   например `tasks`. На бесплатном аккаунте GitHub Pages работает только
   с **публичными** репозиториями (приватный вариант требует GitHub Pro).
   Сам исходный код при этом виден всем — это нормально для такого приложения.
2. Загрузите файлы проекта в корень репозитория (**Add file → Upload files**):
   ```
   index.html
   styles.css
   sw.js
   manifest.webmanifest
   js/            (config.js, storage.js, api.js, app.js)
   icons/         (icon.svg, icon-192.png, icon-512.png, icon-maskable-512.png, apple-touch-icon.png)
   apps-script/Code.gs   ← можно загрузить для хранения, сайту он не нужен
   README.md
   .nojekyll      ← необязательно, но полезно
   ```
   Важно: `index.html` должен лежать в корне репозитория.
3. В репозитории откройте **Settings → Pages**.
4. В блоке **Build and deployment** выберите:
   - Source: **Deploy from a branch**;
   - Branch: **main**, папка **/ (root)**;
   - **Save**.
5. Через 1–2 минуты сайт будет доступен по адресу:
   `https://<ваш-логин>.github.io/tasks/`
6. Откройте ссылку. Сайт покажет «Только это устройство» — это нормально, сейчас настроим синхронизацию.

> Если вместо сайта открывается инструкция «GitHub Pages», подождите пару минут
> и обновите страницу: первая публикация иногда занимает до 10 минут.

### Шаг 3. Подключение синхронизации

**Вариант А — ввести на каждом устройстве (проще, безопаснее):**

1. На сайте нажмите шестерёнку ⚙ (или кнопку «Настроить» в жёлтой плашке).
2. Вставьте URL веб-приложения из шага 1 (`.../exec`) и токен.
3. Нажмите **Проверить связь** — должно появиться «Связь есть. Задач в таблице: 0».
4. Нажмите **Сохранить**. Статус станет «Синхронизировано».
5. Повторите на телефоне: откройте тот же адрес сайта и введите те же два значения.

**Вариант Б — «зашить» настройки в сайт (удобно для телефона):**

1. Откройте файл `js/config.js` в репозитории (кнопка «карандаш»).
2. Заполните:
   ```js
   apiUrl: 'https://script.google.com/macros/s/ВАШ_ID/exec',
   token: 'ВАШ_ТОКЕН',
   ```
3. Закоммитьте изменения. После обновления страницы синхронизация включится сразу.

> Токен в `config.js` виден всем, кто откроет сайт. Подробности — в разделе «Безопасность».

## Установка на телефон

**iPhone / iPad (Safari):**
1. Откройте адрес сайта.
2. Кнопка «Поделиться» → **На экран «Домой»** → «Добавить».

**Android (Chrome):**
1. Откройте адрес сайта.
2. Меню ⋮ → **Установить приложение** (или «Добавить на главный экран»).

После установки приложение открывается без адресной строки и кэширует оболочку,
так что интерфейс работает даже без сети (данные синхронизируются позже).

## Как работает синхронизация

Каждая задача — запись с полями `id`, `title`, `notes`, `done`, `priority`, `due`,
`dueTime`, `createdAt`, `updatedAt`, `deletedAt`.

1. При синхронизации приложение **забирает** все записи из таблицы (`GET ?action=pull`).
2. Локальные и серверные записи сливаются по правилу **Last-Write-Wins**:
   побеждает запись с бо́льшим `updatedAt`. Если время совпало — используется
   детерминированное сравнение содержимого, поэтому оба устройства придут к одному результату.
3. То, что локально новее серверного, **отправляется** в таблицу (`POST action=sync`).
   Сервер применяет тот же алгоритм и возвращает общий список.
4. Удаление — это не физическое удаление строки, а «надгробие»: `deletedAt > 0`.
   Так удаление доезжает до других устройств, даже если они были офлайн.
5. Изменения, сделанные без сети, остаются в `localStorage` и отправляются
   при следующей успешной синхронизации.
6. **Фотографии** синхронизируются отдельно: в задаче хранятся только их id и размеры,
   а сами файлы — на листе `photos` кусками base64 и скачиваются по требованию.
   Фото, которое ещё не ушло в таблицу, помечается в интерфейсе как «ждёт».

Запросы к Apps Script не проходят через service worker и не кэшируются.
Одновременные записи защищены `LockService` на стороне скрипта.

Синхронизация запускается: при открытии сайта, через ~1 секунду после изменения,
раз в `syncIntervalMs` (по умолчанию 60 000 мс), при возврате на вкладку,
при появлении сети и по кнопке «Синхронизировать».

> Часы на устройствах должны быть примерно верными: при сильном расхождении
> «побеждать» будет устройство, у которого время больше.

## Структура таблицы

Лист `tasks`:

| id | title | notes | done | priority | due | createdAt | updatedAt | deletedAt | color | icon | subtasks | photos | dueTime |
|----|-------|-------|------|----------|-----|-----------|-----------|-----------|-------|------|----------|--------|---------|
| UUID | Текст задачи | Заметка | TRUE / пусто | normal / high | 2026-11-20 | мс | мс | мс или пусто | blue… или пусто | 📅 или пусто | JSON | JSON | 09:30 или пусто |

`subtasks` и `photos` — компактный JSON в ячейке:

- подзадача: `{"id":"s1","text":"Купить хлеб","done":false}`;
- фото: `{"id":"…","mime":"image/jpeg","width":1280,"height":960,"size":120000,"createdAt":…}`.

Лист `photos` (создаётся автоматически):

| id | taskId | createdAt | mime | width | height | size | chunkIndex | data |
|----|--------|-----------|------|-------|--------|------|------------|------|
| UUID фото | UUID задачи | мс | image/jpeg | px | px | байт | 0…N | base64 (≤ 40 000 символов) |

Одно фото занимает несколько строк: base64 режется на куски, потому что ячейка Google Таблицы
вмещает 50 000 символов. В задаче хранятся только метаданные, поэтому обычная синхронизация
остаётся быстрой, а файл скачивается при открытии фото.

Служебные функции в `Code.gs` (запускаются вручную из редактора Apps Script):

- `selfTest()` — проверяет логику слияния и доступ к листам;
- `setupSheet()` — создаёт листы `tasks` и `photos` с заголовками;
- `cleanupTombstones(days)` — удаляет старые «надгробия» задач (по умолчанию старше 180 дней);
- `cleanupOrphanPhotos(days)` — удаляет фото, на которые не ссылается ни одна задача
  (например, отменённые черновики; фото моложе 7 дней не трогает).

## Фотографии

- К задаче можно прикрепить до **12 фото**.
- Браузер сам сжимает фото до максимум 1280 px по длинной стороне (JPEG, обычно 60–150 КБ).
- Файл уходит в таблицу через Apps Script (`photoSave`), кусками по 40 000 символов.
- Данные фото хранятся в IndexedDB устройства (localStorage для этого слишком мал),
  поэтому повторно скачивать их с сервера не нужно.
- Если сети нет или синхронизация не настроена, фото остаётся на устройстве
  с пометкой «ждёт» и отправится при первой возможности (кнопка «Синхронизировать», онлайн и т.п.).
- Удаление задачи удаляет и её фото из таблицы (best effort).
- Ограничения Google: 10 млн ячеек на таблицу, поэтому в теории это десятки тысяч фото;
  для личного списка задач места более чем достаточно.


## Обновление приложения

1. Измените файлы в репозитории (можно прямо на github.com: «карандаш» → Commit).
2. Если меняли `styles.css`, `js/*` или `index.html`, **увеличьте версию кэша**
   в `sw.js`: `var CACHE_NAME = 'tasks-app-v4';`
3. На устройстве закройте и откройте приложение (или обновите страницу).
   Service worker подтянет новую версию и удалит старый кэш.

Данные при обновлении не теряются: они лежат в `localStorage` и в Google Таблице.

### Обновление с версии без фото (важно)

Если приложение уже было развёрнуто раньше:

0. Загрузите в репозиторий обновлённые `index.html`, `styles.css`, `sw.js`, `manifest.webmanifest`,
   `js/app.js`, `js/storage.js`, `js/api.js` и **новый файл `js/photos.js`**.
   Файл `js/config.js` не перезаписывайте, если в нём записаны ваш URL и токен.
1. Откройте Apps Script (**Расширения → Apps Script**), замените `Code.gs` новым кодом и сохраните.
2. **Развернуть → Управление развертываниями → карандаш ✏️ → Версия: Новая версия → Развернуть.**
   Так URL веб-приложения не изменится, и настройки на устройствах останутся рабочими.
3. На сайте обновите страницу (`Ctrl+F5`; на телефоне закройте и откройте приложение).
   Колонки `color`, `icon`, `subtasks`, `photos` добавятся в лист `tasks` автоматически.
   Если интерфейс выглядит старым — обновите ещё раз: сначала обновляется service worker,
   затем сами файлы.
4. Лист `photos` появится при первом добавлении фотографии.

В этой версии `CACHE_NAME` уже равен `tasks-app-v3`, поэтому старый кэш обновится сам.

## Локальный запуск (для проверки)

Открыть `index.html` двойным щелчком можно, но синхронизация из `file://`
может блокироваться браузером. Надёжнее поднять локальный сервер:

```powershell
# из папки проекта
python -m http.server 8000
# затем откройте http://localhost:8000
```

Также подойдёт расширение «Live Server» в VS Code.

Проверка логики без сервера: откройте `tests.html` — страница выполнит
юнит-тесты слияния и сортировки и покажет «Все тесты пройдены».

Дополнительные проверки (открывать через локальный сервер, а не `file://`):

| Адрес | Что проверяет |
|---|---|
| `http://localhost:8000/tests.html` | 21 юнит-тест клиентской логики (`js/storage.js`): нормализация, иконки, настройки, слияние |
| `http://localhost:8000/tools/e2e-check.html` | 85 проверок интерфейса в iframe: добавление, фильтры, поиск, редактирование, удаление, цвета, иконки, подзадачи (в диалоге и карточке), фото (бейдж и миниатюра), акцент, сохранение, PWA-ресурсы |
| `http://localhost:8000/tools/backend-check.html` | 45 проверок `apps-script/Code.gs`: нормализация (включая иконки, подзадачи и фото), колонки листа и слияние без обращения к Google |

Страницы проверок пишут результат в заголовок (`OK x/y` или `FAIL x/y`),
поэтому их удобно запускать и в headless-браузере.


## Безопасность

- Доступ к веб-приложению Apps Script — **«Все» (Anyone)**: Google не умеет
  отдавать CORS-ответы для авторизованных браузерных запросов, поэтому вход
  защищён общим **токеном** в каждом запросе.
- Токен — это не пароль от Google-аккаунта. Он даёт доступ только к этому
  списку задач. Если токен попал в чужие руки: поменяйте `TOKEN` в `Code.gs`,
  создайте **новое развертывание** (Deploy → New deployment) и обновите
  URL/токен на устройствах.
- Если вы зашили токен в `js/config.js` публичного репозитория, считайте его публичным.
  Для приватного списка задач это обычно приемлемо, но лучше использовать вариант А
  (ввод настроек на каждом устройстве) либо приватный репозиторий.
- Сама Google Таблица остаётся приватной — доступ к ней есть только у вашего аккаунта.
- Не используйте приложение для паролей, номеров карт и других секретов.

## Устранение неполадок

| Симптом | Причина и решение |
|---|---|
| «Ошибка», в консоли `Failed to fetch` / CORS | В развёртывании Apps Script доступ не «Все» (Anyone). Откройте **Развернуть → Управление развертываниями** и проверьте настройки. |
| `Google вернул не JSON` | Открывается страница входа Google или HTML-ошибка: неверный URL (нужен `/exec`), доступ не «Все», либо скрипт не развёрнут как веб-приложение. |
| «Неверный токен» | `TOKEN` в `Code.gs` и токен в настройках отличаются (лишние пробелы, другая раскладка). |
| «Связь есть», но задачи не появляются на втором устройстве | Нажмите «Синхронизировать» на обоих устройствах. Проверьте, что в таблице действительно есть строки. |
| После правки `Code.gs` ничего не изменилось | Нужно создать **новое развертывание** (изменения в существующем не применяются к `/exec` без новой версии) и взять новый URL. |
| Сайт открывается, но выглядит старым | Обновите страницу с `Ctrl+F5`; при необходимости удалите сайт из service worker (DevTools → Application → Service Workers → Unregister) и откройте заново. |
| На iPhone не устанавливается | Добавлять на экран «Домой» нужно именно из **Safari**. |
| Задачи «прыгают» между версиями | Расхождение часов устройств. Включите автоматическое время на телефоне и ПК. |
| Все задачи пропали после очистки браузера | Локальный кэш удалён, но данные остались в таблице — нажмите «Синхронизировать» после настройки. |
| Фото осталось с пометкой «ждёт» | Нет сети или синхронизация не настроена. Нажмите «Синхронизировать»; после появления интернета фото уйдёт в таблицу и появится на других устройствах. |
| Фото не открывается на другом устройстве | Устройство ещё не скачало файл (нет сети, выключена синхронизация или фото не успело загрузиться). Откройте задачу при интернете и подождите пару секунд. |
| «Не удалось прочитать изображение» | Браузер не поддерживает формат (например, HEIC). Сохраните фото как JPEG/PNG. |
| В таблице нет листа `photos` | Он создаётся при первом добавлении фото. Если фото не добавляются — разверните новую версию `Code.gs` и проверьте токен. |
| После обновления кода нет новых колонок | Разверните новую версию Apps Script (см. «Обновление с версии без фото») и обновите страницу сайта. |
